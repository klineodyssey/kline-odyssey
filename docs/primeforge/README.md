## Deduplication Rules

1. One function has one canonical active file.
2. Same filename and same content: keep one canonical GitHub file only.
3. Same filename but different content: compare version, modified time, lineage and declared source-of-truth before selecting.
4. Old versions are ancestors, not active runtime entries.
5. Do not copy shared system files into temple folders.
6. Do not create `final`, `final_final`, `fix`, `patch`, `hotfix` or version-numbered organ filenames.
7. Version history belongs in document metadata, `RUNTIME_GENOME`, changelog and archive.
8. New PrimeForge system files must be registered in this index and in `/docs/primeforge/PRIMEFORGE_SYSTEM_MANIFEST.json`.
