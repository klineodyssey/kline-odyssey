BscScan's current [official guide](https://info.bscscan.com/how-to-update-token-info/)
requires published contract source and contract-address ownership verification
before the official token-update form. It accepts 32×32 SVG or 64×64 PNG and
requires accessible project links, a neutral description, and a project-domain
email or the primary email published on the project website. A custom-domain
mailbox is therefore not the sole permitted contact route. Ordinary updates
are free; priority service is optional. Do not duplicate an existing request;
establish its status first. These requirements do not establish that either
token has met them.

Trust Wallet's [requirements](https://developer.trustwallet.com/developer/new-asset/requirements.md)
include a full reputable security audit, CoinMarketCap price tracking, and
10,000 holders plus 15,000 transactions, excluding airdropped tokens; the team
may adjust thresholds and retains discretion. Eligibility is not established
for either asset. The old KGEN snapshot's 88 holders is dated July evidence,
not a current count and not a basis for manufacturing activity.

Its [repository details](https://developer.trustwallet.com/developer/new-asset/repository_details.md)
use `blockchains/smartchain/assets/<checksum-address>/logo.png` and
`info.json`. Prefer 256×256 PNG, maximum 100kB, with correct circular cropping
and light/dark contrast. Metadata requires name, BEP20 type, symbol, decimals,
description, website, explorer, status, exact matching ID, links and tags.
Do not insert `status: active` merely because the contract is deployed.
The [fee guide](https://developer.trustwallet.com/developer/new-asset/pr-fee.md)
currently states 500 TWT or 2.5 BNB per PR, including later updates. It is
non-refundable and does not guarantee acceptance. This checkpoint requests
and pays nothing.

CoinGecko's [active-listing guide](https://support.coingecko.com/hc/en-us/articles/7291312302617-How-to-List-a-New-Cryptocurrency-on-CoinGecko)
requires active trading on an exchange it tracks, authenticated submission and
a token-image attachment. Its current
[verification guide](https://support.coingecko.com/hc/en-us/articles/23725417857817-Verification-Guide-for-Listing-Update-Requests-on-CoinGecko)
requires an official social post linked from the project website before filing;
the returned CL/CU request ID must then be added as a reply to that post.
Both public communications need separate authorization. The
[listing terms](https://www.coingecko.com/en/listing_terms) include an authority
warranty and rights to use supplied project data/branding; this review accepts
no agreement. Existing banner dimensions are inventory, not proof of the
current authenticated form's limits. A
[preview listing](https://support.coingecko.com/hc/en-us/articles/40576012083097-How-to-Preview-List-Tokens-on-CoinGecko)
has its own pre-launch/TGE evidence requirements and is not presumed to be a
workaround for an already deployed token without verified trading.
